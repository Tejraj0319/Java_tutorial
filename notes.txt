WHILE LOOP:
   1. Definition: Executes a block repeatedly as long as the condition is `true`.
   2. Syntax:
      while (condition) { // statements }
   3. Execution order: Initialize variable → check condition → execute body → update variable → check condition again.
   4. Condition: Checked before every iteration. If initially `false`, the body executes zero times.
   5. Initialization: Usually done before the loop; sets the starting value.
      int i = 1;
   6. Update: Changes the variable to eventually terminate the loop. Forgetting it may cause an infinite loop.
      i++;
   7. Pre-increment vs post-increment:
      - ++i: increments first, then uses the new value.
      - i++: uses the old value, then increments.
      - In while (i++ <= 10), the old value is compared, but the loop body sees the incremented value.
   8. Loop termination: Stops when the condition becomes `false`. `break` exits immediately; `continue` skips the remaining body and starts the next iteration.
   9. Infinite loop: Happens when the condition never becomes `false`.
       while (true) {}
   10. Practical uses: Repeating until user input is valid, processing data until it ends, menu-driven programs, and loops where the number of iterations is unknown.
   11. Common mistake: A semicolon immediately after `while (condition);` creates an empty loop body.

➤ JAVA STRINGS
   - String is sequence of char.
   - String is nothing but char array.(since we store string sequence in array)
   - under java.lang package.

Q] why string is immutable?
   1) Memory optimization:
   - String literals are stored in special memory called STRING POOL.
   - so multiple variables with same text has a single object in memory so updating one reference variable can lead to change rest of the variables as well.
   e.g. 
   String a = "hi";
   String b = "hi";
   String c = "hi";
   here we have 3 diff var with same text so in string pool there will be only single obj representing "hi" (Memory optimization) changing a or b or c can lead to change other variable as well.
   2)  Security:
   - String can have sensitive data such as password, URL's, network connections so immutability ensures it can't be altered.
   3) Hashcode Caching & Performance:
   - Since string content cannot be changed hashcode value remains same/unchanged and cashed forever.


➤ STRING POOL
   - String pool is special area in heap memory.(part of heap memory)
   - stores string literals.

Q] Haw java stores a string?
   Using string literal:
   - Works in "compile-time".
   - When a string is declared in Java, two separate memory areas are involved:
   1. Stack: Stores the variable reference.
   2. Heap (String Constant Pool): Stores the actual string object value.
   String str1 = "Hello";
   str1 stored in stack and "Hello" stored in  string constant pool inside heap.

   Using new Keyword:
   - Works in "run-time".
   - Using the new keyword forces the JVM to create new objects in the heap outside the String Constant Pool.
   String s1 = new String("abc");
   String s2 = new String("abc");
   here 2 diff objects will get created.

   - Waste of memory

   - On object you can store any type of data.(universal datatype)

        System.out.println(x+5);

* Limitations of using Object as Universal Type: 
   1) Naw this is not good way to handle things suppose data is sensitive then?
   2) There might change of data loss.
   3) Errors might shift to runtime.

   That's haw GENERICS comes into picture
   - Goal is same to store any kind of data without using Object.
   - Take any capital letter and replace with Object keyword. (at all places)
   e.g. private Object value;
   then 
        private T value;
   - That letter is not your datatype it's placeholder.
   - Any class you are treating as generic mention in front of that class in <> and in those brackets mention placeholder name, known as "Type Parameter".

   e.g. class Box<T>{ //Type Parameter
      private T value;
      public T.getValue(){} // getter 
      .
      .
      .
   }

   - Haw to create Obj?

   * Type Inference 
     - In methods while using generics java implicitly decides the type of data while assigning value it is known as Type Inference.

     e.g. printPair(10, "String");

     in this case java will find out that T is int datatype and U is String datatype.
